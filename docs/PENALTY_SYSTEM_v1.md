# سیستم پنالتی (Penalty System) – نسخه ۱

**تاریخ:** ۲۰۲۶-۱۱-۱۳  
**وضعیت:** نهایی‌شده برای پیاده‌سازی  
**مسئول تصمیم:** Grok (Architecture Lead)

---

## هدف سیستم پنالتی

حفظ اعتماد و کیفیت پلتفرم با جلوگیری از رفتارهای مخرب فروشندگان، بدون اینکه سیستم بیش از حد سخت‌گیرانه شود.

اصل کلیدی:  
**فروشنده بعد از ثبت پیشنهاد نمی‌تواند آزادانه آن را لغو کند.** اگر بخواهد انصراف دهد، باید پنالتی بپذیرد.

---

## ۱. موارد ایجاد پنالتی

| مورد | شدت | توضیح |
|------|------|--------|
| لغو پیشنهاد بعد از ثبت (قبل از پذیرش خریدار) | متوسط | رایج‌ترین مورد |
| عدم ارسال کالا بعد از پرداخت خریدار | شدید | خیانت در امانت |
| ارسال کالای مغایر با پیشنهاد | شدید | |
| تأخیر غیرموجه در ارسال | متوسط تا شدید | |
| رفتار نامناسب یا توهین | متوسط تا شدید | بر اساس گزارش |
| سوءاستفاده تکراری از سیستم | بسیار شدید | |

---

## ۲. انواع پنالتی (قابل ترکیب)

### الف) کاهش امتیاز اعتبار (Reputation Score)
- هر کاربر یک امتیاز اعتبار از ۰ تا ۱۰۰ دارد (شروع از ۸۰).
- لغو پیشنهاد ساده: −۵ تا −۱۰ امتیاز
- تخلف متوسط: −۱۵ تا −۲۵ امتیاز
- تخلف شدید: −۳۰ تا −۵۰ امتیاز

### ب) محدودیت موقت قیمت‌دهی (Offer Restriction)
- فروشنده برای مدت مشخص نمی‌تواند پیشنهاد جدید ثبت کند.
- مدت‌ها:
  - تخلف خفیف: ۱۲ تا ۲۴ ساعت
  - تخلف متوسط: ۳ تا ۷ روز
  - تخلف شدید: ۱۴ تا ۳۰ روز

### ج) محدودیت دریافت درخواست (اختیاری در موارد شدید)
- فروشنده برای مدت مشخص از استخر درخواست‌ها اعلان نمی‌گیرد.

### د) مسدودیت کامل حساب (فقط در موارد بسیار شدید و با تأیید ادمین)

---

## ۳. قوانین دقیق لغو پیشنهاد

1. فروشنده می‌تواند پیشنهاد خود را **قبل از پذیرش خریدار** لغو کند، اما پنالتی اعمال می‌شود.
2. بعد از پذیرش پیشنهاد توسط خریدار و پرداخت، فروشنده **حق لغو یک‌طرفه ندارد**.
3. اگر فروشنده بعد از پرداخت کالا را نفرستد یا مغایر بفرستد → پنالتی شدید + امکان بازپرداخت کامل به خریدار از طریق اسکرو.

---

## ۴. محاسبه خودکار شدت پنالتی

سیستم بر اساس این فاکتورها شدت را تعیین می‌کند:

- تعداد پنالتی‌های قبلی فروشنده در ۳۰ روز گذشته
- امتیاز اعتبار فعلی
- زمان باقی‌مانده تا انقضای پیشنهاد (هرچه نزدیک‌تر به انقضا، پنالتی سنگین‌تر)
- آیا خریدار پیشنهاد را دیده/نگه داشته یا نه

---

## ۵. ساختار پیشنهادی جدول (برای schema_v2)

جدول فعلی `penalties` خیلی ساده است. نسخه کامل‌تر:

```sql
CREATE TABLE IF NOT EXISTS penalties (
  id                  INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id             INTEGER NOT NULL REFERENCES users(id),
  offer_id            INTEGER REFERENCES request_offers(id),
  order_id            INTEGER REFERENCES orders(id),
  
  reason_code         TEXT NOT NULL,          -- cancel_offer | no_ship | wrong_item | delay | abuse | other
  reason_text         TEXT NOT NULL,
  severity            TEXT NOT NULL,          -- light | medium | heavy | critical
  
  reputation_deduction INTEGER NOT NULL DEFAULT 0,
  restriction_hours   INTEGER NOT NULL DEFAULT 0,  -- مدت محدودیت قیمت‌دهی (ساعت)
  block_requests      INTEGER NOT NULL DEFAULT 0,  -- ۱ = محدودیت دریافت درخواست
  
  restriction_until   TEXT,
  is_active           INTEGER NOT NULL DEFAULT 1,
  
  applied_by          TEXT DEFAULT 'system',  -- system | admin
  admin_id            INTEGER REFERENCES users(id),
  admin_note          TEXT,
  
  created_at          TEXT NOT NULL DEFAULT (datetime('now'))
);
```

---

## ۶. نمایش به کاربر

- فروشنده همیشه دلیل پنالتی و مدت محدودیت را واضح می‌بیند.
- خریدار فقط نتیجه را می‌بیند (مثلاً «این فروشنده اخیراً چند پیشنهاد را لغو کرده»).
- امتیاز اعتبار فروشنده در پروفایل عمومی نمایش داده می‌شود (به صورت ستاره یا درصد).

---

## ۷. قوانین محافظتی

- پنالتی‌های خودکار قابل اعتراض هستند (از طریق تیکت).
- ادمین می‌تواند پنالتی را کاهش دهد یا لغو کند.
- سیستم نباید کاربر تازه‌کار را با اولین اشتباه سنگین تنبیه کند (تخفیف برای کاربران جدید).

---

## ۸. ارتباط با ناشناس بودن

تا قبل از پرداخت، هویت فروشنده کاملاً مخفی است.  
حتی اگر پنالتی بخورد، خریدار هویت او را نمی‌بیند مگر اینکه معامله به مرحله پرداخت برسد.
