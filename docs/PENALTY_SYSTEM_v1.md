## هدف سیستم پنالتی

حفظ اعتماد و کیفیت پلتفرم با جلوگیری از رفتارهای مخرب فروشندگان، بدون اینکه سیستم بیش از حد سخت‌گیرانه شود.

اصل کلیدی:  
**فروشنده بعد از ثبت پیشنهاد نمی‌تواند آزادانه آن را لغو کند.** اگر بخواهد انصراف دهد، باید پنالتی بپذیرد.

---

## وضعیت پیاده‌سازی (۱۹ نوامبر ۲۰۲۶)

### انجام‌شده:
- سرویس پنالتی کامل
- لغو پیشنهاد → اعمال خودکار پنالتی
- بررسی محدودیت هنگام ثبت پیشنهاد جدید
- کاهش امتیاز اعتبار
- ثبت در سابقه + اعلان به کاربر
- API: `POST /api/offers/:id/cancel` و `GET /api/penalties/my`

### مقادیر پیش‌فرض فعلی (قابل تنظیم توسط سوپر ادمین):
| دلیل | شدت | کاهش امتیاز | مدت محدودیت |
|------|------|-------------|-------------|
| لغو پیشنهاد (`cancel_offer`) | متوسط | −۸ | ۲۴ ساعت |
| عدم ارسال کالا (`no_ship`) | شدید | −۲۵ | ۷ روز |
| کالای مغایر (`wrong_item`) | شدید | −۲۰ | ۵ روز |
| تأخیر (`delay`) | متوسط | −۱۰ | ۴۸ ساعت |
| سوءاستفاده (`abuse`) | بسیار شدید | −۴۰ | ۳۰ روز |

## جزئیات فنی کد

### فایل‌های اصلی

| فایل | نقش |
|------|-----|
| `src/services/penalty.ts` | منطق اصلی پنالتی |
| `src/services/offer.ts` | بررسی محدودیت هنگام ثبت پیشنهاد + فراخوانی لغو |
| `src/routes/offer.ts` | endpointهای cancel و لیست پنالتی |

### توابع مهم در `penalty.ts`

#### ۱. `applyPenalty(env, input)`
اعمال پنالتی روی کاربر.

**ورودی:**
- `userId`
- `reasonCode` (مثل `cancel_offer`)
- `reasonText`
- اختیاری: `offerId`, `orderId`, `severity`, `appliedBy`, `adminId`

**کارهایی که انجام می‌دهد:**
1. ثبت رکورد در جدول `penalties`
2. کاهش `reputation_score` در `user_profiles` (حداقل صفر)
3. ثبت در `activity_logs`
4. ایجاد اعلان درون‌برنامه‌ای برای کاربر

**خروجی:** `{ ok: true, penaltyId, restrictionUntil }`

#### ۲. `checkOfferRestriction(env, userId)`
بررسی می‌کند آیا کاربر الان محدودیت ثبت پیشنهاد دارد یا نه.

**خروجی:**
- `{ restricted: false }` → آزاد است
- `{ restricted: true, until, reason }` → محدود است

#### ۳. `cancelOfferWithPenalty(env, sellerId, offerId)`
لغو پیشنهاد + اعمال پنالتی در یک عملیات.

**مراحل:**
1. بررسی مالکیت و وضعیت پیشنهاد
2. تغییر وضعیت پیشنهاد به `cancelled_with_penalty`
3. فراخوانی `applyPenalty` با دلیل `cancel_offer`
4. برگرداندن پیام واضح به کاربر

#### ۴. `getUserPenalties(env, userId)`
لیست پنالتی‌های کاربر (برای نمایش در پروفایل یا صفحه جداگانه).

---

### جریان دقیق لغو پیشنهاد

```
فروشنده → POST /api/offers/:id/cancel
         ↓
cancelOfferWithPenalty()
         ↓
1. بررسی پیشنهاد متعلق به فروشنده است؟
2. وضعیت پیشنهاد = active است؟
3. وضعیت را به cancelled_with_penalty تغییر بده
4. applyPenalty() را صدا بزن
   - ثبت در جدول penalties
   - کم کردن امتیاز اعتبار
   - ساخت اعلان
5. پیام موفقیت + تاریخ پایان محدودیت برگردان
```

### جریان بررسی هنگام ثبت پیشنهاد جدید

```
فروشنده → POST /api/offers
         ↓
createOffer()
         ↓
checkOfferRestriction()
         ↓
اگر restricted = true → خطا برگردان (اجازه ثبت نده)
اگر restricted = false → پیشنهاد را ثبت کن
```

---

### ساختار جدول `penalties` (استفاده‌شده)

فیلدهای مهم:
- `user_id` — کسی که پنالتی خورده
- `offer_id` / `order_id` — مرتبط با کدام پیشنهاد/سفارش
- `reason_code` — کد دلیل (cancel_offer و ...)
- `reason_text` — توضیح فارسی
- `severity` — light | medium | heavy | critical
- `reputation_deduction` — مقدار کم‌شده از امتیاز
- `restriction_hours` — مدت محدودیت به ساعت
- `restriction_until` — تاریخ و ساعت پایان محدودیت
- `is_active` — آیا هنوز فعال است
- `applied_by` — system یا admin

### APIها

| متد | مسیر | توضیح |
|-----|------|--------|
| `POST` | `/api/offers/:id/cancel` | لغو پیشنهاد + اعمال پنالتی |
| `GET` | `/api/penalties/my` | لیست پنالتی‌های کاربر فعلی |
| `POST` | `/api/offers` | ثبت پیشنهاد (با چک محدودیت) |

**نمونه پاسخ موفق لغو:**
```json
{
  "success": true,
  "message": "پیشنهاد لغو شد. تا ۱۴۰۴/۰۸/۳۰، ۱۲:۰۰ نمی‌توانید پیشنهاد جدید ثبت کنید."
}
```

**نمونه خطا هنگام ثبت پیشنهاد در حالت محدودیت:**
```json
{
  "error": "شما به دلیل پنالتی تا ... نمی‌توانید پیشنهاد جدید ثبت کنید. دلیل: لغو پیشنهاد بعد از ثبت"
}
```

## قوانین مهم کسب‌وکار

1. پنالتی **بدون پول** است.
2. در فاز اول فقط روی فروشنده اعمال می‌شود.
3. خریدار فعلاً آزاد است.
4. تمام اعداد (ساعت و امتیاز) توسط سوپر ادمین قابل تنظیم خواهد بود.
5. پنالتی خودکار قابل اعتراض از طریق تیکت است.
