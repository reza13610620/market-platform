# همگام‌سازی کاتالوگ کالا بین مارکت‌پلتفرم و ربات تلگرام (Foo)

**تاریخ:** ۲۰۲۶-۱۱-۱۹  
**وضعیت:** طراحی اولیه – آماده تصمیم‌گیری  
**مسئول:** Grok

---

## ۱. سؤال شما

آیا می‌شود دیتابیس‌های کالا را به هم وصل کرد تا هر جا کالا تعریف شد، طرف دیگر خودکار آپدیت شود؟

**جواب کوتاه:** بله، کاملاً ممکن است. هر دو روی Cloudflare Workers + D1 هستند.

---

## ۲. وضعیت فعلی

| پروژه | دیتابیس | ساختار کالا |
|--------|---------|-------------|
| مارکت‌پلتفرم | D1 جدا | جدول `products` + دسته‌بندی + بارکد + صف بررسی |
| ربات Foo (@Baristatools_bot) | D1 جدا | کاتالوگ درختی (حدود ۶۷۶ نود) + قوانین خاص Special plan |

دو دیتابیس **جدا** هستند. مستقیم به هم وصل نیستند.

---

## ۳. گزینه‌های فنی (از ساده به حرفه‌ای)

### گزینه A – دیتابیس مشترک (Shared D1) ⭐ پیشنهادی برای شروع

- یک D1 مشترک فقط برای **کاتالوگ کالا** بسازید (مثلاً `shared-catalog`).
- هر دو Worker به همان D1 بایند شوند.
- جدول مشترک مثلاً:

```sql
shared_products (
  id, title, brand, category_path, barcodes_json,
  attributes_json, status, source,   -- source: 'market' | 'bot' | 'both'
  market_product_id, bot_node_id,
  created_at, updated_at
)
```

**مزیت:** ساده‌ترین راه، بدون API اضافی، همیشه هم‌خوان.  
**عیب:** باید ساختار کالا را کمی یکسان کنیم؛ ربات و مارکت هر کدام فیلدهای اضافه خودشان را دارند.

### گزینه B – همگام‌سازی با API (دو دیتابیس جدا)

- مارکت‌پلتفرم منبع اصلی کاتالوگ عمومی باشد.
- وقتی ادمین کالا را در مارکت تأیید کرد → یک درخواست امن به Worker ربات زده شود (`POST /internal/catalog/upsert`).
- ربات هم اگر کالا پیشنهاد کرد و تأیید شد → به مارکت اطلاع دهد.
- کلید مشترک مخفی (secret) بین دو Worker برای امنیت.

**مزیت:** استقلال کامل دو پروژه.  
**عیب:** کمی پیچیده‌تر؛ باید retry و لاگ همگام‌سازی داشته باشیم.

### گزینه C – فقط یک‌طرفه (مارکت → ربات)

- فعلاً فقط وقتی در مارکت کالا تأیید شد، به ربات هم اضافه شود.
- ربات کماکان کاتالوگ خودش را دارد و بعداً می‌تواند دوطرفه شود.

---

## ۴. پیشنهاد عملی من (برای الان)

**مرحله ۱ (سریع و کم‌ریسک):**
1. مارکت‌پلتفرم **منبع اصلی** کاتالوگ عمومی باشد.
2. بعد از `approve` کالا در مارکت، یک webhook/API داخلی به ربات صدا زده شود.
3. ربات کالا را در کاتالوگ خودش (یا جدول مشترک) ثبت/به‌روز کند.
4. فیلد `external_id` / `market_product_id` برای جلوگیری از تکراری بودن.

**مرحله ۲ (بعداً):**
- اگر خواستید دوطرفه شود، ربات هم هنگام تأیید کالا، به مارکت اطلاع دهد.
- یا به Shared D1 مهاجرت کنید.

---

## ۵. نکات مهم کسب‌وکاری

- ربات فعلاً فقط پلن Special می‌تواند کالا پیشنهاد دهد؛ مارکت برای همه باز است → قوانین تأیید ممکن است فرق کند.
- نام‌گذاری و دسته‌بندی ربات درختی است؛ مارکت دسته‌بندی تخت‌تر دارد → نیاز به نگاشت (mapping) دسته داریم.
- بارکد بهترین کلید یکتایی بین دو سیستم است (اگر وجود داشته باشد).
- کالاهای رد‌شده یا غیرفعال نباید به طرف دیگر بروند.

---

## ۶. امنیت

- endpoint همگام‌سازی باید فقط با `Authorization: Bearer <SYNC_SECRET>` کار کند.
- secret در هر دو Worker به‌صورت Secret ذخیره شود.
- لاگ تمام همگام‌سازی‌ها در `activity_logs` یا جدول `catalog_sync_log`.

---

## ۷. تصمیم لازم از شما

لطفاً یکی را انتخاب کنید:

1. **گزینه A** – دیتابیس مشترک کاتالوگ  
2. **گزینه B** – دو دیتابیس + API همگام‌سازی دوطرفه  
3. **گزینه C** – فعلاً فقط مارکت → ربات (یک‌طرفه)

بعد از انتخاب شما، جزئیات فنی دقیق (جدول‌ها + کد endpoint) را می‌نویسم.
