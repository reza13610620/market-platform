# بازخورد دوطرفه + امتیاز سیستمی + پنالتی تصاعدی – نسخه ۱

**تاریخ:** ۲۰۲۶-۱۱-۱۹  
**وضعیت:** طراحی نهایی + پیاده‌سازی بک‌اند انجام شد  
**مسئول تصمیم:** Grok (Architecture Lead)

---

## ۱. هدف

- هر دو طرف معامله (خریدار و فروشنده) بتوانند بعد از اتمام معامله به هم امتیاز بدهند.
- هر کاربر یک **امتیاز سیستمی** داشته باشد که برای همه قابل مشاهده است.
- این امتیاز فقط توسط سیستم محاسبه شود و کاربران عادی نتوانند آن را تغییر دهند.
- فقط ادمین بتواند در موارد خاص (از طریق تیکت) آن را تنظیم کند.
- پنالتی برای تکرار تخلف **تصاعدی** باشد (هر بار سنگین‌تر).

---

## ۲. امتیاز سیستمی (Reputation Score)

### قوانین اصلی

| مورد | توضیح |
|------|--------|
| بازه | ۰ تا ۱۰۰ |
| شروع برای کاربر جدید | ۸۰ |
| قابل مشاهده | بله، برای همه |
| قابل تغییر توسط کاربر عادی | خیر |
| قابل تغییر توسط ادمین | فقط در موارد خاص (تیکت) |
| محاسبه | کاملاً خودکار توسط سیستم |

### عوامل تأثیرگذار روی امتیاز (خودکار)

| عامل | تأثیر |
|------|--------|
| بازخورد مثبت از طرف مقابل | افزایش |
| بازخورد منفی از طرف مقابل | کاهش |
| پنالتی (لغو پیشنهاد، عدم ارسال و ...) | کاهش |
| تکمیل موفق معامله | افزایش جزئی |
| تعداد معاملات موفق زیاد | افزایش تدریجی |
| عدم فعالیت طولانی | بدون تغییر (امتیاز حفظ می‌شود) |

### فرمول ساده پیشنهادی (مرحله ۱)

```
امتیاز پایه = ۸۰

+ (میانگین امتیاز دریافتی از بازخوردها − ۳) × ۸
+ تعداد معاملات موفق × ۰.۵   (حداکثر +۱۰)
− مجموع کاهش‌های پنالتی

نتیجه بین ۰ تا ۱۰۰ محدود می‌شود.
```

**نکته:** این فرمول ساده است و بعداً قابل تنظیم توسط سوپر ادمین خواهد بود.

### نمایش به کاربر

- در پروفایل عمومی: عدد امتیاز + برچسب ساده (مثلاً «عالی»، «خوب»، «متوسط»، «ضعیف»)
- در لیست پیشنهادها: امتیاز فروشنده نمایش داده می‌شود (ناشناس تا لحظه مشاهده اطلاعات تماس)

## ۳. بازخورد دوطرفه (Feedback / Review)

### زمان ثبت بازخورد

فقط بعد از **تکمیل معامله** (وضعیت سفارش = completed).

### قوانین

1. هم خریدار و هم فروشنده می‌توانند به هم امتیاز بدهند (۱ تا ۵ ستاره + توضیح اختیاری).
2. هر طرف فقط **یک‌بار** می‌تواند به طرف مقابل امتیاز بدهد.
3. بازخورد بعد از ثبت قابل ویرایش نیست (برای جلوگیری از سوءاستفاده).
4. بازخورد فقط بعد از تکمیل معامله فعال می‌شود.
5. اگر یکی از طرفین بازخورد ندهد، طرف دیگر همچنان می‌تواند امتیاز بدهد.

### جدول reviews (از قبل وجود دارد)

```sql
reviews (
  id, order_id, reviewer_id, reviewee_id,
  rating (1-5), comment, created_at
  UNIQUE(order_id, reviewer_id)
)
```

### APIهای پیاده‌سازی‌شده

| متد | مسیر | توضیح |
|-----|------|--------|
| `POST` | `/api/orders/:id/review` | ثبت بازخورد |
| `POST` | `/api/orders/:id/complete` | علامت‌گذاری معامله به عنوان تکمیل‌شده |
| `GET` | `/api/users/:id/reviews` | لیست بازخوردهای یک کاربر (عمومی) |
| `GET` | `/api/me/reviews` | بازخوردهایی که من داده‌ام / دریافت کرده‌ام |
| `GET` | `/api/me/orders` | لیست سفارش‌های من (با وضعیت can_review) |

### جریان فاز فعلی (بدون اسکرو کامل)

1. خریدار روی «نمایش اطلاعات تماس» کلیک می‌کند.
2. سیستم یک **سفارش سبک** با وضعیت `contact_revealed` می‌سازد.
3. بعد از هماهنگی خارج از پلتفرم، هر کدام از طرفین می‌تواند با `POST /api/orders/:id/complete` معامله را تکمیل کند.
4. بعد از completed شدن، هر دو طرف می‌توانند بازخورد بدهند.

## ۴. پنالتی تصاعدی

### اصل

هر بار که فروشنده دوباره تخلف کند، پنالتی سنگین‌تر می‌شود.

### جدول تصاعدی برای «لغو پیشنهاد» (رایج‌ترین مورد)

| تعداد پنالتی فعال در ۳۰ روز گذشته | کاهش امتیاز | مدت محدودیت |
|-----------------------------------|-------------|-------------|
| اولین بار | −۸ | ۲۴ ساعت |
| دومین بار | −۱۲ | ۴۸ ساعت |
| سومین بار | −۱۸ | ۷۲ ساعت |
| چهارم و بیشتر | −۲۵ | ۷ روز |

### برای تخلفات شدیدتر (عدم ارسال، کالای مغایر)

| تعداد | کاهش امتیاز | مدت محدودیت |
|-------|-------------|-------------|
| اولین بار | −۲۵ | ۷ روز |
| دومین بار | −۴۰ | ۱۴ روز |
| سومین بار و بیشتر | −۵۰ + بررسی ادمین | ۳۰ روز یا مسدودیت |

### نحوه محاسبه در کد

سیستم قبل از اعمال پنالتی، تعداد پنالتی‌های مشابه در ۳۰ روز گذشته را می‌شمارد و بر اساس آن شدت را انتخاب می‌کند.

## ۵. تغییر دستی امتیاز توسط ادمین

- فقط ادمین می‌تواند امتیاز را دستی تغییر دهد.
- دلیل تغییر باید ثبت شود (مثلاً «اصلاح بعد از تیکت شماره ۱۲۳»).
- تغییر در `activity_logs` ثبت می‌شود.
- کاربر اعلان دریافت می‌کند که امتیازش توسط پشتیبانی تنظیم شده است.

---

## ۶. قوانین مهم

1. امتیاز سیستمی **هرگز** توسط کاربر عادی قابل تغییر نیست.
2. بازخورد فقط بعد از معامله کامل‌شده ممکن است.
3. پنالتی تصاعدی است تا تکرار تخلف هزینه بیشتری داشته باشد.
4. ناشناس بودن حفظ می‌شود: تا قبل از مشاهده اطلاعات تماس، فقط امتیاز دیده می‌شود نه هویت.
5. تمام اعداد (ضرایب، مدت‌ها، آستانه‌ها) توسط سوپر ادمین قابل تنظیم خواهند بود.
